# CLAUDE.md — Project Brief for Claude Code

This file briefs Claude Code (running in Antigravity) on this project: what it is, what's been built so far, and the rules to follow while working in this repo. Read this before making any changes.

## What this project is

**Convert PDF** (deployed at converttpdf.com) is a client-side document/image conversion web app. Everything runs in the browser — no backend, no database, no file uploads to a server. It converts and manipulates PDFs and images (merge, split, rotate, compress, crop, resize, format conversion, watermarking, PDF ↔ Word, PDF ↔ image, etc.) entirely in-memory using JavaScript libraries (pdf-lib, pdf.js, jsPDF, docx, mammoth, SheetJS, JSZip) plus the Canvas and File APIs, then delivers the result as a local download. Note: despite older wording in this repo, the app does not execute WebAssembly at runtime — `pdfjs-dist` ships optional `.wasm` codecs, but `wasmUrl` is never configured and no `.wasm` file is bundled or served.

The product's core pitch is privacy: files never leave the user's device.

## Tech stack

- React 19 + Vite 7, TypeScript
- Routing: TanStack Router / TanStack Start (`@tanstack/react-router`, `@tanstack/react-start`) — routes live in `src/routes/`, auto-generated tree in `src/routeTree.gen.ts` (do not hand-edit)
- Styling: Tailwind CSS v4, Radix UI primitives, Framer Motion
- Processing libraries: `pdf-lib`, `pdfjs-dist`, `mammoth`, `docx`, `jszip`, `xlsx`, Canvas API for images
- Deployment: Cloudflare Workers (`server.ts` is the SSR/Workers entry point, `wrangler.toml` / `wrangler.jsonc` configure it)
- Package manager: this repo has both `bun.lock` and `package-lock.json` — check with the user which one is actually in use before adding dependencies
- Originally scaffolded with Lovable (see `.lovable/project.json`)
- Linting/formatting: ESLint + Prettier (`npm run lint`, `npm run format`)
- No test suite yet (unit tests are on the roadmap, not implemented)

## What's been achieved so far (per git history)

The project has gone through several build phases already:

1. Initial scaffold, footer/nav refinements, safety/trust content added.
2. Domain connected (converttpdf.com), DNS + SEO setup, sitemap work.
3. Terms/privacy/policy pages added; site published live and submitted for AdSense review.
4. Blog pages added for SEO and AdSense purposes.
5. Multiple SEO passes: schema markup, sitemap `lastmod` fixes, trust signals.
6. Rich content added to individual tool pages (PDF tools, then image tools) to differentiate them for SEO instead of having near-duplicate thin pages.
7. A cleanup sprint removed fabricated testimonials, a non-functional pricing section, misleading mock ad UI, and a deceptive rewarded-ad download gate (an ad-gating pattern that was flagged as user-hostile/deceptive and stripped out across all tools).

**Current state:** the site is live in production on converttpdf.com, monetized via ads (see `src/config/ads.ts`, `src/components/ads/`, `src/hooks/monetization/useRewardedDownload.tsx`), and mid-refinement — there's an uncommitted change in progress on `src/lib/pdf-compress-utils.ts` and `CompressPdfPanel.tsx` (PDF compression logic).

Known limitations (not bugs to "fix" without discussion): the homepage PDF ↔ Word converter caps files at 25MB (browser memory limits) — the dedicated tool pages have no fixed cap and are bounded by device memory; no OCR (scanned PDFs won't extract text); no automated tests yet. PDF compression defaults to the "medium" preset, which re-encodes embedded images as JPEG at 75% quality — only the "low" preset is lossless.

## Rules for working in this repo

1. **Never commit or push directly.** Do not run `git commit`, `git push`, or otherwise write to git history on your own initiative. Stage/prepare changes and let Soham review and commit himself, unless he explicitly tells you in that session to commit. Never push to `main`/`origin` under any circumstance without being explicitly asked in that specific instance.
2. **No new branches or PRs without being asked.** Don't assume a git workflow beyond what's requested — ask if unsure.
3. **This is a live production site.** converttpdf.com is published and earning AdSense revenue. Treat every change as something that could affect real users and ad review status — avoid speculative refactors, don't remove trust/legal pages (privacy, terms, disclaimer, cookie), and don't touch ad/monetization config unless that's the explicit task.
4. **Don't reintroduce what was deliberately removed.** Fabricated testimonials, fake pricing tables, mock/misleading ad UI, and deceptive ad-gates before downloads were intentionally stripped out in prior sprints — don't add anything like that back.
5. **Don't hand-edit generated files** — `src/routeTree.gen.ts` is auto-generated by the TanStack router plugin; regenerate it via the dev/build process instead.
6. **Run lint/format before calling anything done:** `npm run lint` and `npm run format`. There's no test suite to run yet.
7. **Keep it client-side.** No backend/database should be introduced without explicit discussion — the whole privacy pitch depends on files never leaving the browser. `server.ts` is only an SSR/static-serving shim for Cloudflare Workers, not an app backend.
8. **SEO matters.** Tool pages were deliberately given unique rich content instead of thin/duplicate templates — when adding new tool pages, follow that pattern rather than copy-pasting boilerplate.
9. **Ask before adding dependencies or changing the build/deploy config** (`vite.config.ts`, `wrangler.toml`/`wrangler.jsonc`, `package.json` scripts) — these are tuned for the Cloudflare Workers deployment.
10. **When in doubt, ask Soham rather than guessing** — especially for anything touching monetization logic, legal/policy pages, or git operations.
